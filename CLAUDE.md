# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An extension to GSD, written in TypeScript on Node ≥ 24 and shipped as the npm package `gsd-toolkit`, installed from the GitHub release (`curl … install.sh | bash`, which runs `npm install -g` on the release's `.tgz` and then `gsdt-setup`; the npm registry is optional). It runs on macOS, Linux and Windows without WSL (Git for Windows required). The bash launchers in `bin/` remain for running from a checkout; the repo's shims, the `tests/*.sh` suites and the installers (`install.sh`, `lib/install.sh` = the bridge from 0.10.x) are still bash. It does three things:

1. **Adds worktree support to GSD.** Each phase runs in its own `phase-<N>-<slug>` git worktree, so phases can run in parallel.
2. **Wraps repeated GSD steps in simple commands.** `gsdt-start`, `gsdt-list`, `gsdt-finish`, `gsdt-doctor`, and the others replace multi-step manual sequences (for example: claim phase → push → create worktree → open session).
3. **Is agent-agnostic.** Claude Code, Codex, and `custom` are adapters. Several providers can work in one project, and hand off one phase between them: `gsdt-start -p <N> --provider <name>` reuses the phase's worktree and artifacts. Handoff is **sequential**. Concurrent writers in one worktree are not safe; run parallel providers on different phases. The cross-AI plan review uses a configurable `review_provider` (default `codex`).

This repo is the **single source of truth**: target repos carry only `.gsd.conf`, the frozen shims, and generated instruction blocks. User docs: `README.md`, `docs/features.md` (full feature list), `docs/providers.md` (capability matrix + full `.gsd.conf` key reference), `docs/architecture.md`, `docs/migration.md`, `docs/releases.md`, and `docs/command-order.html` (phase order).

GSD itself (gsd-core, `@opengsd/gsd-core`: the `/gsd-*` planning skills, including `gsd-review`, and the `gsd_run` CLI) is upstream and **not** in this repo. The toolkit knows nothing of the old GSD (`get-shit-done-cc`, `gsd-sdk`): no fallback, no detection. `gsdt-setup` installs gsd-core where an agent has none, and `gsdt-update` updates it (`src/core.ts`). `gsdt-start` claims phases with `gsd_run query phase.add` / `phase.insert` — no LLM call. Outside tools: Node ≥ 24 and `git` (on Windows, Git for Windows: its `sh` runs the shims, hooks, merge driver and pre-merge script), `npm`/`npx` (install, gsd-core), `gh` (for `gsdt-finish --pr`). No Python, Perl or `jq` is used at runtime (the repo hook merge into `.claude/settings.json` is native). Optional: `curl` (only for the ClickUp API with `tracker = clickup`, token in `~/.config/gsd/clickup.env`), Playwright (`gsdt-ui check`).

## Commands

Everything is `node:test` (Node >= 24 runs the `.ts` files directly). The old bash suites are gone.

```sh
npm ci && npx tsc --noEmit                     # types
node --test 'tests/node/*.test.ts' 'tests/ts/*.test.ts' 'tests/os/*.test.ts'   # everything (what CI runs; ~6-10 min)
node --test tests/node/doctor.test.ts           # one file
UPDATE_GOLDEN=1 node --test tests/ts/p5-doctor.test.ts   # regenerate saved goldens, then check `git diff tests/golden`
GSD_PLAYWRIGHT_ROOT=<dir> node --test tests/node/ui-browser.test.ts   # real browser (<dir> has playwright + chromium); skips without it
GSD_TEST_REQUIRE_GSD=1 node --test tests/node/e2e.test.ts             # real gsd-core `gsd_run`; the skip becomes a failure

# Lint (CI, Ubuntu only): what bash is left
for f in bin/* install.sh lib/install.sh shims/scripts/*.sh shims/scripts/hooks/*.sh tools/*.sh; do bash -n "$f"; done
shellcheck -x bin/* install.sh lib/install.sh shims/scripts/*.sh shims/scripts/hooks/*.sh tools/*.sh
```

Install = a GitHub release (`curl -fsSL …/main/install.sh | bash`, then `gsdt-update`). Edits here never reach an installed command until a release: try them with `<checkout>/bin` first on `PATH`. Release (maintainer): add "## X.Y.Z" to CHANGELOG.md, commit, then `tools/release.sh X.Y.Z --push`.

## Architecture

**Core vs adapters.** The core is `src/common.ts`, `src/planning.ts`, `src/roadmap.ts`, `src/guard.ts`, `src/commands/flow-next.ts` (the worktree rules and the step engine) and the other `src/commands/`. It may call `src/provider.ts`, but adapters must never hold phase state, merge, claim, or safety policy. To add a provider, extend `src/provider.ts` (identity, instruction file, skill root, argv renderer, review flag, hook metadata), the CLI allowlists/help, docs, and the provider tests (`tests/node/providers.test.ts`, `tests/ts/`) — see `docs/architecture.md`.

- **`bin/`**, **`src/commands/`**, **`src/launch.mjs`** — every command is `src/commands/<name>.ts` exporting `main(argv): number | Promise<number>` (no work at import time; it returns the exit code, so a test can call it). `package.json` `bin` lists 24 `gsdt-*` entries, each `dist/bin/gsdt-<name>.js`, made by `tools/build.mjs`; all go through `src/launch.mjs`, which checks Node ≥ 24 (a clear message, not a syntax error), loads `src/commands/<name>.ts` from a checkout or `dist/commands/<name>.js` from npm, and honours `GSD_SKIP_GUARD`. `bin/gsdt-*` are small bash launchers (symlink walk, `node` check, `exec node src/launch.mjs <name>`) kept for running from a checkout (`GSD_PKG` = the package dir); `bin/gsdt-planning-merge` and `bin/gsdt-worktree-guard` keep their fail-safe logic in bash (a merge driver must never exit nonzero; the guard must exit 2, never 1). Commands: user-facing `gsdt-init`, `gsdt-start`, `gsdt-list` (STAGE `verify` = every plan ran but the ROADMAP row is not ticked; `done` only when ticked), `gsdt-finish`, `gsdt-doctor` (`--all [<folder>...]`: one line per GSD repo, from the registry `~/.config/gsd/repos` (`src/repos.ts`; written best-effort by `gsdt-init`, `gsdt-bootstrap-repo`, `gsdt-start`, `gsdt-finish` — never by doctor) plus a scan of each folder for set-up repos (`toolkitRepo`); `src/doctor-all.ts`), `gsdt-repos` (= `gsdt-doctor --all`), `gsdt-setup` (machine setup after `npm i -g`: skills, the Claude user hooks, gsd-core, moving a 0.10.x install off `~/.local/bin`; no `postinstall`; `src/commands/setup.ts`), `gsdt-update` (npm mode: the latest release from GitHub, its `.tgz` checked against `SHA256SUMS`, `npm install -g` on it + the new `gsdt-setup --no-core`, then gsd-core; a checkout updates nothing; a 0.10.x release runtime hands over to its `install.sh`), `gsdt-rules` (prints the toolkit's rules; `--hook` for Claude's SessionStart), `gsdt-notify` (a desktop notification when a session waits; `--hook` for Claude's `Notification` and `PreToolUse(AskUserQuestion)` user hooks: set-up repos only, silent, always exit 0, the text passed to `osascript`/`notify-send` as arguments, never as script), `gsdt-bootstrap-repo`, `gsdt-planning-repair`, `gsdt-tracker` (the only tracker command; `gsd-clickup` is gone — never re-add it), `gsdt-ui`, `gsdt-codex-wait`, `gsdt-batch` (makes a `batch-*` worktree, then a fresh session there running `/gsdt-batch`, Claude on Sonnet; refuses when `.planning/` is not committed, since gsd-core then runs in the main checkout), `gsdt-batch-report`, `gsdt-migrate` (moves a repo set up before 0.10.0 to the gsdt-* names: shims, pre-merge script, exact path references, repo hook, marked blocks, this clone's driver/tracker section/post-merge hook, the user's Claude hooks; `--check` for doctor T090, repo + clone only; `--apply` then asks to commit the repo files it changed (steps 1–5 only, path-limited, never pushes; `--commit` = yes without asking; no TTY and no `--commit` = no commit, it prints the command; doctor `--fix` runs it with no stdin)). Internal: `gsdt-wt-new` / `gsdt-wt-finish` (worker halves of start/finish), `gsdt-worktree-guard`, `gsdt-flow-next`, `gsdt-planning-merge` (git merge driver), `gsdt-derive-port`. A command that runs another toolkit command finds it on `PATH`, or runs it through `process.execPath` + `launch.mjs` (`src/spawn.ts`).
- **`src/common.ts`** — config (`confGet` reads `.gsd.conf`; keys fall back to detection), `findMain`, base branch, worktree dir, the checkout lock (`.git/gsd-cmd.lock`, dead-PID reclaim via `process.kill(pid, 0)`, same `pid` file format as the bash), merge-driver registration, the reviews/validation checks, the finish gates, and `planningStatus`/`planningApply` — the one definition of "installed" shared by doctor and bootstrap. Conventions: camelCase without the old `gsd_` prefix (`gsd_main` → `findMain`); resolvers return `Result<T>`; a bash `exit` became `throw new GsdExit(code, msg)`; a signal stops a command that holds the lock, and the next command reclaims the dead lock.
- **`src/provider.ts`** (+ **`src/rules-text.ts`**) — the provider adapters. No workflow logic. Resolves provider, executable, model and start mode (precedence tables in `docs/providers.md`); renders argv safely (arrays, never a shell string, never `eval`); names a launched Claude session (`sessionResolve`: `--name`, and `--remote-control <name>` — always with the name, its value is optional and a bare flag would take the prompt); owns the marked-block helpers for generated instruction files and the text of every generated block.
- **`src/guard.ts`** (entry `src/commands/worktree-guard.ts`) — the guard's rules. The Claude hook JSON is parsed natively with the semantics the old `jq` path had (plugin form `gsd-core:gsd-x` → `gsd-x`, `gsdt-flow` and the pre-0.8.0 `gsdw-flow` → `gsd-flow` for matching, while BLOCKED texts name `/gsdt-flow`; `//` treats null/false as missing; one leading `/` stripped). No node, an old Node or a runtime error: `--global` exits 0 silently (fail open), otherwise one `BLOCKED: …` line and exit 2 (never 1: Claude reads non-2 as "allow"); `GSD_SKIP_GUARD=1` exits 0 before node is needed.
- **`src/codex-wait.ts`** — for `gsdt-codex-wait`: parses Codex's usage-limit message ("try again at Oct 11th, 2026 1:22 AM" = local time, minutes only) and finds the newest limited run in `$CODEX_HOME/sessions/**.jsonl`; a log line whose `timestamp` is older than the wait's start is no limit. Reads files only; nothing here may call Codex.
- **`src/batch-report.ts`** — for `gsdt-batch-report`: finds `/gsd-quick-batch` / `/gsdt-batch` runs in `~/.claude/projects/<cwd, non-alnum → ->/*.jsonl` and counts tokens per role. A batch ends at the next batch, `/clear`, a done line (`gsdt-batch: done items=N …`, `QUICK BATCH COMPLETE`), or the first typed prompt once SETTLED (no helper's own log has a later line; every planned quick id has an executor). Helpers link to their `Agent` call by meta `toolUseId`, else the call's result `agentId`. Usage once per `message.id`, tool calls once per `tool_use` id. Transcript text is matched, never printed.
- **`src/claude-settings.ts`** (+ **`src/pyjson.ts`**) — edit Claude settings files and keep every other key: `claudeEnv` sets or removes one `env` variable (`compactSettings` in `src/provider.ts` uses it so a phase worktree's `.claude/settings.local.json` carries `compact_at` for a plain `claude`), `baserefState`, `removeGuardHook`. They write JSON byte-for-byte as Python did (numbers like `1.0`, `1e5` and big ints stay as they were): never swap them for `JSON.parse`/`JSON.stringify` on a user's settings file.
- **`src/hook-paths.ts`** — for doctor T008 and the `gsdt-start`/`gsdt-list` warning (`staleHooks`): lists GSD hooks (a word names a `gsd-*` or `gsdt-*` program) in each agent's user settings (`providerUserHookFile`) and the repo's, whose absolute paths are gone. Other hooks are never reported. Doctor only names the fix (re-run GSD's installer, or the toolkit's); it never edits these files.
- **`src/planning.ts`** — `reconcile` (one file, structural only, run mid-merge by the driver) and `repair` (both files + recompute counters from `.planning/phases/*/*-PLAN.md`/`*-SUMMARY.md`; `--check` for CI).
- **`src/roadmap.ts`** (entries `src/commands/roadmap-rows.ts`, `roadmap-audit.ts`) — the rows `gsdt-start` adds after each claim (the checklist + Progress rows gsd-core (`gsd_run`) omits, so the new phase passes the audit) and the read-only ROADMAP audit for `gsdt-doctor` (T021–T023): it catches two upstream gsd-core (`gsd_run`) bugs (`phase.insert` writes no checklist row; `phase.complete` can tick another phase's row).
- **`bin/gsdt-tracker`** + **`src/commands/tracker.ts`** + **`src/tracker/`** — tickets (see `docs/trackers.md`). **Standalone**: these files import only `node:*` and each other (`src/tracker/winexec.ts` is its own copy of the process layer), never `src/common.ts` or any other GSD module; nothing else in `src/` imports `src/tracker/` (its twin is `src/ticket.ts`); a test runs the tracker from a folder holding only these files, and a lint checks the imports. GSD runs it only as a command. Settings (`src/tracker/config.ts`, `trkGet`): env > git config `gsdt-tracker.*` (`.git/config`, per clone) > `.gsd.conf` `tracker*` keys (read only) > default (`none` with a `.gsd.conf`, else `clickup`). `gsdt-tracker config` prints them offline as `key=value` with `<key>_from`; `gsdt-doctor` reads that (T018, T071–T073). `gsdt-tracker login [<name>]` works in any folder: saves `~/.config/gsd/clickup-<name>.env` (asks use-or-replace when it exists), and in a git repo sets `git config gsdt-tracker.profile`; it never edits `.gsd.conf`. `src/tracker/cli.ts` knows no tracker's commands: shared verbs (`start`, `finish`, `comment`, `status`, `snapshot`, `create`, `update`, `tasks`, `check`) go to the connector's run function; a connector's own commands are in its `TRACKER_EXTRA`. To add a tracker, add `src/tracker/<name>.ts` (a run function and `TRACKER_EXTRA`, like `clickup.ts`), then extend `trkKnown` (`config.ts`) and the dispatch in `cli.ts`. Tracker calls are best-effort: failures print a note and never block start/finish. ClickUp is reached by running `curl` from PATH (tests stub it); the JSON work is native (`src/tracker/json.ts`).
- **`src/ticket.ts`** — the GSD side: a phase links to a ticket by the tag `tk-<id>` at the end of its title and slug; the id is read back from the ROADMAP title first (the slug is lowercased). Legacy `cu_<id>` tags, `--cu`, and `STORY.md` are read, never written. `ticketNorm`/`ticketExtract` are twins of `trkIdNorm`/`trkIdExtract` (`src/tracker/ids.ts`); a test (`tests/ts/p9-ticket.test.ts`) keeps them equal. `trackerWhich` asks `gsdt-tracker config` and counts only a tracker that is SET — gsdt-tracker's own `clickup` default is `none` for GSD.
- **`src/ui.ts`** — the UI quality gates (`docs/ui-quality-plan.md`, `docs/plan-ui-check.md`), one definition for `gsdt-flow-next` (steps design-system, layout, ui-check, ui-look, ui-approve), the guard (rule 5, `ui_gates = strict`), `gsdt-wt-finish` / `gsdt-finish --pr` (`uiFinishGate`), doctor (T080, T081, T040 UI debt) and `gsdt-ui`. `uiGate` is the ONE answer to "which UI step is open" — never re-derive it in a caller. Artifacts: `.planning/design/DESIGN.md` (stub marker until filled; `- R<n>:` layout rules), `<P>-LAYOUT.md` (`sketch:` = a `/gsd-sketch` folder whose README has a `winner:`, `pages:`, `url:`, `app:`, per-page `main_button:` / `expect:`, `waive:`), `<P>-UI-CHECK.md` (capture id + code hash), `<P>-UI-LOOK.md`, `<P>-UI-APPROVAL.md`, pictures + sheet in `<P>-SHOTS/` (git-ignored). Staleness = `uiInputsState` (`uiCodeState`, a tree hash of the working files outside `.planning/` built in a throwaway index, `+` the hash of `<P>-LAYOUT.md`) differs from the check's `code:` (an older check with no `+` is compared on the code hash only). A phase is exempt only when its `<P>-UI-REVIEW.md` is already on the base branch. `ui_gates = warn` (default) / `strict` / `off`. Bootstrap never creates `.planning/` (it would flip `/gsd-ingest-docs` into merge mode); the stub is made by the flow step.
- **`src/ui-check.ts`** (entry `src/commands/ui-check.ts`) — the Node runner behind `gsdt-ui check` (checks C1–C8, pictures, sheet, report). It resolves the PROJECT's Playwright with `createRequire` (a toolkit script cannot `import` project packages), falling back to the global npm folder (`uiGlobalRoot`; tests pin `GSD_NPM_GLOBAL_ROOT` so the machine's own install never changes a result), uses the library API only (never a Playwright config), and writes into a run folder that `gsdt-ui` publishes only when the run finished. `lib/vendor/axe-core/` is a pinned copy (MPL-2.0, with its license); update `VERSION` with it. Everything the sheet shows is HTML-escaped. Doctor never imports or launches any of this.
- **`src/context.ts`** — doctor's context section (`docs/plan-context-doctor.md`): `coreRequiredSkills` (the gsd-core skills the flow and `gsdt-init` run — T009 checks these, not the profile name), the listing size of gsd-core's skills/agents (chars / 4), and the skill groups safe to hide (read from gsd-core's `clusters.cjs` with node, minus `.gsd-surface.json`'s disabled ones; a group is hideable only when none of its skills is required). Notes only; never edits gsd-core's files.
- **`src/spawn.ts`** (+ `src/stdio.ts`, `src/tracker/winexec.ts`) — the process and path layer; every child process goes through it. On macOS/Linux a pass-through. On Windows: a bare command is resolved on PATH × PATHEXT (Node does not do that), `.exe` runs directly, `.cmd`/`.bat` through `cmd.exe` with every argument escaped, and anything else (an extensionless stub, a hook, the pre-merge script) as `sh <script>` (Git for Windows). `normalizePath` makes git's `C:/…` and Node's paths comparable; `shellPath` writes forward slashes into hooks and scripts. Session launches (`gsdt-start`, `gsdt-batch`, `gsdt-init`) go through async `runSession` (`src/stdio.ts`): INT/QUIT are ignored by the launcher, TERM/HUP passed on (what `exec` gave in bash). Text is read as `\r\n` or `\n` and written LF; STATE.md's Session Continuity stays byte-identical on Windows too. `src/stdio.ts` `out`/`err` write unbuffered so lines interleave with git's in order.
- **Install and releases** (`docs/releases.md`) — `VERSION` is the package version. **npm package, shipped by the GitHub release (0.11.0 onwards):** `install.sh` (top level; bash, also Git Bash; needs curl, node ≥ 24, npm) reads the latest tag from the GitHub API (or `--version`), downloads `SHA256SUMS` + `gsd-toolkit-X.Y.Z.tgz` (a release without that line is refused with its own installer's curl line), verifies sha256, runs `npm install -g` on the file, then `node <npm root -g>/gsd-toolkit/src/launch.mjs setup <options>` with `GSD_BIN_DIR` = npm's bin dir (the hooks point there even when it is not on PATH) and stdin closed (under `curl | bash` stdin is the script). `release.yml` builds the `.tgz` (`npm pack`; refuses package.json ≠ VERSION) and the `.tar.gz` (`git archive`, for 0.10.x installers); `SHA256SUMS` lists both; `tools/release.sh` writes `VERSION` + `package.json` + lock. **The bridge:** `lib/install.sh` is what an installed 0.10.x runs (its `install.sh` / `gsdt-update` download the `.tar.gz` and run `bash lib/install.sh` with `GSD_BIN_DIR`/`GSD_COPY_DIR`, stdin `/dev/null`): it unsets `GSD_BIN_DIR GSD_COPY_DIR GSD_RELEASES_DIR` (gsdt-setup would take `~/.local/bin`, which it empties, as the hook dir) and `exec`s the package's `install.sh --version <its VERSION>` with the agent/hook/core options. Nothing is removed before the npm install succeeded, so a bridge that fails (no node, bad download) leaves the 0.10.x install intact. Never change what `lib/install.sh` is called with without re-running `tests/node/install.test.ts` (it uses the real v0.10.0 scripts). `npm i -g gsd-toolkit` from the registry also works once published; nothing depends on it. `npm install -g` puts the `package.json` `bin` entries on PATH (npm writes the Windows wrappers); `files` ships `bin/`, `dist/`, `src/launch.mjs`, `lib/vendor/`, `shims/`, `skills/`, `VERSION`, `CHANGELOG.md` — no other `lib/` file. `gsdt-setup` (`src/commands/setup.ts`) does the machine part; it finds its bin dir from `GSD_BIN_DIR`, else the first PATH folder whose `gsdt-worktree-guard` resolves into this package, writes the user hooks with that path (`shellPath`), and records the agents in `~/.config/gsd/setup-manifest`. It replaces skills it placed earlier (`<!-- gsd-toolkit-skill X.Y.Z -->` line at the end of SKILL.md) in place instead of making `.bak` copies — a `.bak` in a skill dir would load as real — and removes a 0.10.x install (`~/.local/bin` links, `~/.local/share/gsd-toolkit`, its manifest). `installMode()` (`src/version.ts`): `.git` → checkout, `install.sh` beside it → a 0.10.x release runtime, else npm. `src/version.ts` holds the day-long cached latest-version check (the GitHub release, in every mode; never the npm registry for the toolkit); `gsdt-start`/`gsdt-list` print the notice only when stderr is a tty (`GSD_UPDATE_NOTICE=always` forces it in tests) from a detached refresh child (`update-refresh`, not a public command), `gsdt-doctor` always notes it. The update repo for the release line is `malyeg/gsd-toolkit` (`GSD_UPDATE_REPO` overrides). **0.10.x release line (bash, frozen — only data-loss fixes; it moves to 0.11.0 through the bridge, no last 0.10.x release needed):** the OLD `install.sh` (tag v0.10.0; standalone, `curl | bash`) downloads a release tarball + `SHA256SUMS`, verifies, and runs that package's `lib/install.sh` into `…/share/gsd-toolkit/releases/<X.Y.Z>/`. From 0.11.0 that `lib/install.sh` is the bridge above; `tests/node/install.test.ts` runs the real old scripts against it. **Old name:** before 0.8.0 the package was `gsd-worktrees` (`arconme/gsd-worktrees`, archived). Write only new names. Since 0.11.0 the machine-level legacy (`share/gsd-worktrees/`, the `gsd-worktrees-X.Y.Z.tar.gz` name, the old skill mark, `gsdw-*` skills) is no longer read; the repo-level `gsd-worktrees:<kind>:start/end` instruction markers still are (`GSD_MARK_RE`; rewritten in place by bootstrap, T016 until then).
- **`shims/`** — frozen 7-line delegators that bootstrap copies into target repos as `scripts/gsdt-*.sh`. Keep them unchanged: 0.10.0's rename (`scripts/gsd-*.sh` → `gsdt-*`) was the one change, and `gsdt-migrate` moves a repo over.
- **`mods/gsdt-batch-sonnet/`** — a Claude Code mod (hooks module, `register.ts`): while `/gsdt-batch` runs, MAIN-session `turn.step` requests go to `sonnet` (`e.agentId === undefined` only); off at the skill's `gsdt-batch: done` line, an aborted turn, session end, `/gsdt-batch-off`. Not installed by `install.sh`. Check it with `claude plugin validate` + `claude plugin test mods/gsdt-batch-sonnet` (local only: CI has no `claude`).
- **`skills/`** — `gsdt-worktrees`, `gsdt-flow`, `gsdt-tracker`, `gsdt-doctor` and `gsdt-batch`, installed per agent (install removes a toolkit skill it no longer ships). Never name a skill `gsd-*`: gsd-core's installer deletes every `skills/gsd-*` folder. They must stay provider-neutral: no literal `Skill()` calls. The flow skill only interprets `gsdt-flow-next` output; it is not a second state machine. Likewise `gsdt-doctor` only acts on `gsdt-doctor --json` (asking first); doctor itself stays read-only.

**Enforcement.** The mandatory guard is provider-neutral: `gsdt-worktree-guard --command … --phase … --repo …`. `gsdt-start` calls it before it prints or launches a session, and `gsdt-flow-next` calls it before it returns a step. Native hooks are extra defense only: Claude `PreToolUse(Skill)`. Codex has none. Exit 2 = block. The only escape hatch is `GSD_SKIP_GUARD=1`. One hook is user-level, not per repo: `gsdt-setup` registers `gsdt-worktree-guard --global` in `~/.claude` settings (next to the skills dir; `--no-user-hook` opts out) so `/gsd-new-project` and `/gsd-ingest-docs` are refused before `gsdt-init` (rule 0). It fires in every repo, so outside a set-up repo (`toolkitRepo`: `.gsd/INSTRUCTIONS.md`, the finish shim, or a `.gsd.conf` key other than `tracker*` — a tracker-only `.gsd.conf` is not one) `--global` applies rule 0 only — never widen that. In a set-up repo it applies every rule (it is the only hook that sees typed slash commands; the repo hook sees `Skill` calls). It fails open on a payload it cannot read.

**Generated instructions (in target repos).** The workflow rules are not copied into repos: `gsdt-rules` prints them for the installed release (`rulesText`; + the repo's values via `repoValues`, and the screens paragraph unless `ui_gates = off`). Claude loads them with a user-level `SessionStart` hook (`gsdt-rules --hook`, registered by `gsdt-setup` next to the guard's `--global` hook; `--no-user-hook` drops both; it prints nothing outside a set-up repo (`toolkitRepo`) and always exits 0; keep its output well under ~10 KB, Claude Code cuts a larger one to a file). Codex/custom run `gsdt-rules` from the `AGENTS.md` line. `.gsd/INSTRUCTIONS.md` is canonical but small (providers, base, worktree dir — never `flow`/`ui_gates`, which `gsdt-rules` reads live — a core that holds without the toolkit, a pointer), between `canonical:start`/`end` markers. All block text lives in `src/rules-text.ts` and `src/provider.ts` (`rulesText`, `canonicalBlock`, `providerEntryBlock`): bootstrap writes it and doctor compares against it (T016 = out of date; T062 = Claude cannot load `gsdt-rules`), so edit it only there. `CLAUDE.md` / `AGENTS.md` (Codex + custom share it) get only a marked `gsd-toolkit:provider:start`/`end` entrypoint (`gsd-worktrees:` before 0.8.0, still read). Bootstrap validates markers before writing and never touches text outside them.

**Finish path.** `gsdt-finish` → `gsdt-wt-finish`: sync origin (abort on failure) → the gates (`finishGates`: `uiFinishGate`, then with `flow = strict` `flowFinishGate`, the test audit; they read the branch from a throwaway worktree when its own is gone) (then `verifyDebtGate`: a warning, never a refusal, when every plan ran but the ROADMAP row is not ticked — repeated after the merge line) → validate the phase (`scripts/gsdt-premerge-check.sh` — run through `sh` on Windows, where it needs no exec bit — else the project's tests) → merge → `gsdt-planning-repair` (from `PATH`, else the package's own launcher; if it cannot run, the finish stops before any push) → validate the combined tree → push with retry (repair and validate again after each retry's pull) → remove worktree + branch (files the finish's own test run left are removed; any other change keeps the worktree, exit 0) → `gsdt-tracker finish` (only with a tracker set). A failed validation keeps local commits and the worktree, and never pushes.

## Invariants to keep

- **`gsd-*` = gsd-core, `gsdt-*` = this toolkit.** Never name a command, shim or skill `gsd-*` (a lint in `tests/node/commands.test.ts` checks `bin/` and `shims/`). Since 0.10.0 there are no old-name aliases; what still reads an old name does so only to move it (`gsdt-migrate`, `gsdt-setup` removing a 0.10.x install and replacing old user hooks, `gsdt-tracker` reading the `gsd-tracker.*` git section, legacy detection in bootstrap/doctor). Not renamed on purpose: the merge driver key `gsd-planning` (open worktrees' `.gitattributes` name it), `.gsd.conf`, `.gsd/`, `GSD_*`, `.git/gsd-cmd.lock`. (The bash `gsd_*` functions became camelCase in `src/`.)
- One phase = one `phase-<N>-<slug>` worktree; one batch = one `batch-<date>-<slug>` worktree (`gsdt-batch` → `gsdt-wt-new --batch`; `gsdt-finish` lands it without the per-phase gates). The main checkout stays on the base branch. Find a phase's branch with `phaseBranch` (a `/gsd-pr-branch` helper `X-pr` is skipped only when `X` exists, so a slug may end in `-pr`).
- Claims serialize through the base branch (pull, push, rebase-and-retry; the loser renumbers).
- A failed merge or validation must leave the remote base branch untouched.
- A `<P>-REVIEWS.md` counts only when `reviewsProblem` (`src/common.ts`) finds nothing: `gsdt-flow-next` and the guard share it. A review cut short by a usage limit is never a pass.
- The phase-flow artifact list (`<P>-CONTEXT.md`, `<P>-REVIEWS.md`, `<P>-REVIEW.md`, `<P>-VALIDATION.md` (`validationProblem`), `<P>-UI-REVIEW.md`, `<P>-LAYOUT.md`, `<P>-UI-CHECK.md`, `<P>-UI-LOOK.md`, `<P>-UI-APPROVAL.md`, …) is shared by `gsdt-flow-next`, the guard's `flow = strict` and `ui_gates = strict` rules, the finish gates (`flowFinishGate`, `uiFinishGate`), and gsdt-doctor's T040 report. Change them together.
- A UI check that could not run must never leave an older pass in place, and "not checked" is never reported as passed.
- Planning reconcile: keyed lines keep the **first** occurrence's position and the **best** occurrence's content (`[x]` beats `[ ]`, longer wins among equals). Single-value lines keep the last copy (the incoming branch). STATE.md's `## Session Continuity` must stay byte-identical — a test asserts it.
- `gsdt-doctor` is read-only by default. `--fix` (opt-in, asks y/N or `--yes`) runs only named safe actions — `gsdt-init --no-launch --no-commit`, `gsdt-planning-repair`, `git branch --track <base>`, `chmod +x` the pre-merge script (not on Windows, which has no exec bit), remove a dead lock — dispatched by name, never by eval of fix text; it never commits, pushes, checks out, deletes branches or edits ROADMAP.md. Add a code to the safe list only if its fix is mechanical and undoable. Finding codes: `W0xx` are shared with `/gsd-health`, `T0xx` are toolkit-only (e.g. `T050` bad providers list, `T059` bad model).
- `gemini` is refused with a reason everywhere (`providers`, `--provider`, `--agent`, `GSD_AGENT`, `review_provider`, `install.sh --agent`, `lib/install.sh --agent`); `gsdt-init --no-launch` removes an older release's Gemini setup.
- Legacy configs keep working: a singular `provider` key, `agent_command`, `--agent`, and `GSD_AGENT` are read-only compatibility inputs. With no provider configured, the default is Claude.
- **Bash that is left** — the `bin/` launchers, `shims/`, and `install.sh` / `lib/install.sh` (the installers: npm way and the bridge). The rules in the next two bullets apply to those only; the TypeScript has no bash 3.2 or BSD/GNU concerns. macOS runs bash 3.2. There, `"$VAR…"` (a variable touching a non-ASCII character) is read as an unknown variable, and with the lock's EXIT trap an "unbound variable" crash **exits 0**. Always brace: `${VAR}…`. `tests/node/commands.test.ts` lints for it. Bash 3.2 also brace-expands `{2,4}` inside nested `"$( … "$( … )" )"` quotes: put such a regex in a variable first. Phase numbers may be zero-padded (`08`, `02.1` from gsd-core): never feed them to `$(( ))` without `10#`, and compare them numerically, not as strings (in TypeScript too: parse with base 10, never as octal).
- Bash scripts must work on both BSD (macOS) and GNU userlands. Shellcheck exceptions go in `.shellcheckrc` with a reason.
- **TypeScript rules.** Node ≥ 24, no runtime dependencies (`node:*`, `fetch`, `node:test`; Playwright stays the project's own, resolved with `createRequire`). Only erasable syntax (`erasableSyntaxOnly`: no `enum`, no parameter properties), so `src/*.ts` runs directly and `tsc` builds `dist/`; imports between files use the `.ts` extension. Run `git` and providers with an argument array through `src/spawn.ts`, never a shell string or `eval`. Every command keeps its name, flags, output and exit codes. A path from git (`C:/…` on Windows) is compared only after `normalizePath`.
- **Windows.** Git for Windows' `sh` runs everything shell-shaped in a target repo (shims, post-merge hook, merge driver command, Claude hooks, the pre-merge script). Hooks and the merge driver are written with forward-slash paths (`shellPath`). CI runs every test on `windows-latest` too, in shards (`tests/shards.json`; `tests/win-preload.ts` is loaded there; `tests/bail-reporter.mjs` stops a shard after `GSD_TEST_MAX_FAILS` failures). Arguments to a script run through `sh` are quoted by `shArgs` (`src/spawn.ts`); compare paths under a root with `relUnder`, never `startsWith(root + "/")`; HOME falls back to `USERPROFILE`.
- `lib/` holds only `install.sh` (the 0.10.x bridge, live for that line) and `lib/vendor/` (shipped). The old bash/python/perl code and its suites are gone: the TS tests compare against saved goldens in `tests/golden/` (`tests/ts/golden.ts`, `UPDATE_GOLDEN=1` to regenerate).
