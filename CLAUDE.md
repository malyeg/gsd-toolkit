# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An extension to GSD, written as a bash toolkit (plus six Python modules, two Perl scripts, and one Node script for the browser check). It does three things:

1. **Adds worktree support to GSD.** Each phase runs in its own `phase-<N>-<slug>` git worktree, so phases can run in parallel.
2. **Wraps repeated GSD steps in simple commands.** `gsdt-start`, `gsdt-list`, `gsdt-finish`, `gsdt-doctor`, and the others replace multi-step manual sequences (for example: claim phase → push → create worktree → open session).
3. **Is agent-agnostic.** Claude Code, Codex, and `custom` are adapters. Several providers can work in one project, and hand off one phase between them: `gsdt-start -p <N> --provider <name>` reuses the phase's worktree and artifacts. Handoff is **sequential**. Concurrent writers in one worktree are not safe; run parallel providers on different phases. The cross-AI plan review uses a configurable `review_provider` (default `codex`).

This repo is the **single source of truth**: target repos carry only `.gsd.conf`, the frozen shims, and generated instruction blocks. User docs: `README.md`, `docs/features.md` (full feature list), `docs/providers.md` (capability matrix + full `.gsd.conf` key reference), `docs/architecture.md`, `docs/migration.md`, `docs/copy-install.md`, and `docs/command-order.html` (phase order).

GSD itself (gsd-core, `@opengsd/gsd-core`: the `/gsd-*` planning skills, including `gsd-review`, and the `gsd_run` CLI) is upstream and **not** in this repo. The toolkit knows nothing of the old GSD (`get-shit-done-cc`, `gsd-sdk`): no fallback, no detection. `install.sh` installs gsd-core where an agent has none, and `gsdt-update` updates it (`lib/core.sh`). `gsdt-start` claims phases with `gsd_run query phase.add` / `phase.insert` — no LLM call. Other outside tools: `git`, Python 3.7+, `perl`, `gh` (for `gsdt-finish --pr`), `jq` (optional; doctor hook checks and the ClickUp tracker), and — only with `tracker = clickup` — the ClickUp API (token in `~/.config/gsd/clickup.env`).

## Architecture

**Core vs adapters.** The core is `bin/`, `lib/common.sh`, the planning reconciler, the worktree rules, and `gsdt-flow-next`. It may call `lib/provider.sh`, but adapters must never hold phase state, merge, claim, or safety policy. To add a provider, extend `lib/provider.sh` (identity, instruction file, skill root, argv renderer, review flag, hook metadata), the CLI allowlists/help, docs, and `tests/test-providers.sh` — see `docs/architecture.md`.

- **`bin/`** — user-facing: `gsdt-init`, `gsdt-start`, `gsdt-list`, `gsdt-finish`, `gsdt-doctor`, `gsdt-update`, `gsdt-rules` (prints the toolkit's rules; `--hook` for Claude's SessionStart), `gsdt-bootstrap-repo`, `gsdt-planning-repair`, `gsdt-tracker` (the only tracker command; `gsd-clickup` is gone — never re-add it), `gsdt-ui`, `gsdt-codex-wait`, `gsdt-batch` (launcher: makes a `batch-*` worktree, then a fresh session there running `/gsdt-batch`, Claude on Sonnet; refuses when `.planning/` is not committed, since gsd-core then runs in the main checkout), `gsdt-batch-report`, `gsdt-migrate` (moves a repo set up before 0.10.0 to the gsdt-* names: shims, pre-merge script, exact path references, repo hook, marked blocks, this clone's driver/tracker section/post-merge hook, the user's Claude hooks; `--check` for doctor T090, repo + clone only). Internal: `gsdt-wt-new` / `gsdt-wt-finish` (worker halves of start/finish), `gsdt-worktree-guard`, `gsdt-flow-next`, `gsdt-planning-merge` (git merge driver), `gsdt-derive-port`. Each script finds its package via `GSD_PKG` (from its own resolved path) and sources `lib/`.
- **`lib/common.sh`** — config (`gsd_conf_get` reads `.gsd.conf`; keys fall back to detection), `gsd_main`, base branch, worktree dir, the checkout lock (`.git/gsd-cmd.lock`, dead-PID reclaim), merge-driver registration, and `gsd_planning_status`/`gsd_planning_apply` — the one definition of "installed" shared by doctor and bootstrap.
- **`lib/provider.sh`** — the provider adapters. No workflow logic. Resolves provider, executable, model and start mode (precedence tables in `docs/providers.md`); renders argv safely (never `eval`); owns the marked-block helpers for generated instruction files.
- **`lib/gsd_hook_payload.py`** — the guard's fallback when jq is missing: turns Claude's hook JSON into the guard's NUL-delimited input (plugin form `gsd-core:gsd-x` → `gsd-x`, `gsdt-flow` and the pre-0.8.0 `gsdw-flow` → `gsd-flow`).
- **`lib/gsd_codex_limit.py`** — for `gsdt-codex-wait`: parses Codex's usage-limit message ("try again at Oct 11th, 2026 1:22 AM" = local time, minutes only) and finds the newest limited run in `$CODEX_HOME/sessions/**.jsonl`. Reads files only; nothing here may call Codex.
- **`lib/gsd_batch_report.py`** — for `gsdt-batch-report`: finds `/gsd-quick-batch` / `/gsdt-batch` runs in `~/.claude/projects/<cwd, non-alnum → ->/*.jsonl` and counts tokens per role. A batch ends at the next batch, `/clear`, a done line (`gsdt-batch: done items=N …`, `QUICK BATCH COMPLETE`), or the first typed prompt once SETTLED (no helper's own log has a later line; every planned quick id has an executor). Helpers link to their `Agent` call by meta `toolUseId`, else the call's result `agentId`. Usage once per `message.id`, tool calls once per `tool_use` id. Transcript text is matched, never printed.
- **`lib/gsd_claude_env.py`** — sets or removes one `env` variable in a Claude settings file, keeping every other key; `gsd_compact_settings` (`lib/provider.sh`) uses it so a phase worktree's `.claude/settings.local.json` carries `compact_at` for a plain `claude`.
- **`lib/gsd_hook_paths.py`** — for doctor T008 and the `gsdt-start`/`gsdt-list` warning (`gsd_stale_hooks` in `lib/provider.sh`): lists GSD hooks (a word names a `gsd-*` or `gsdt-*` program) in each agent's user settings (`gsd_provider_user_hook_file`) and the repo's, whose absolute paths are gone. Other hooks are never reported. Doctor only names the fix (re-run GSD's installer, or the toolkit's); it never edits these files.
- **`lib/gsd_planning.py`** — `reconcile` (one file, structural only, run mid-merge by the driver) and `repair` (both files + recompute counters from `.planning/phases/*/*-PLAN.md`/`*-SUMMARY.md`; `--check` for CI).
- **`lib/roadmap-rows.pl`** — run by `gsdt-start` after each claim: adds the checklist + Progress rows gsd-core (`gsd_run`) omits, so the new phase passes `roadmap-audit.pl`.
- **`bin/gsdt-tracker`** + **`lib/tracker/`** — tickets (see `docs/trackers.md`). **Standalone**: `bin/gsdt-tracker` and `lib/tracker/*` never source `lib/common.sh` (or any GSD lib) nor call a `gsd_*` function (their own use `trk_*`); a test runs them from a folder holding only those files, and a lint checks it. GSD runs it only as a command. Settings (`lib/tracker/config.sh`, `trk_get`): env > git config `gsdt-tracker.*` (`.git/config`, per clone) > `.gsd.conf` `tracker*` keys (read only) > default (`none` with a `.gsd.conf`, else `clickup`). `gsdt-tracker config` prints them offline as `key=value` with `<key>_from`; `gsdt-doctor` reads that (T018, T071–T073). `gsdt-tracker login [<name>]` works in any folder: saves `~/.config/gsd/clickup-<name>.env` (asks use-or-replace when it exists), and in a git repo sets `git config gsdt-tracker.profile`; it never edits `.gsd.conf`. `bin/gsdt-tracker` knows no tracker's commands: shared verbs (`start`, `finish`, `comment`, `status`, `snapshot`, `create`, `update`, `tasks`, `check`) go to the connector's `tracker_run`; a connector's own commands are in its `TRACKER_EXTRA`. To add a tracker, add `lib/tracker/<name>.sh` defining `tracker_run` (and `TRACKER_EXTRA`), then extend `trk_known`. Tracker calls are best-effort: failures print a note and never block start/finish.
- **`lib/ticket.sh`** — the GSD side: a phase links to a ticket by the tag `tk-<id>` at the end of its title and slug; the id is read back from the ROADMAP title first (the slug is lowercased). Legacy `cu_<id>` tags, `--cu`, and `STORY.md` are read, never written. `gsd_ticket_norm`/`gsd_ticket_extract` are twins of `trk_id_norm`/`trk_id_extract` (`lib/tracker/ids.sh`); a test keeps them equal. `gsd_tracker_which` asks `gsdt-tracker config` and counts only a tracker that is SET — gsdt-tracker's own `clickup` default is `none` for GSD.
- **`lib/ui.sh`** — the UI quality gates (`docs/ui-quality-plan.md`, `docs/plan-ui-check.md`), one definition for `gsdt-flow-next` (steps design-system, layout, ui-check, ui-look, ui-approve), the guard (rule 5, `ui_gates = strict`), `gsdt-wt-finish` / `gsdt-finish --pr` (`gsd_ui_finish_gate`), doctor (T080, T081, T040 UI debt) and `gsdt-ui`. `gsd_ui_gate` is the ONE answer to "which UI step is open" — never re-derive it in a caller. Artifacts: `.planning/design/DESIGN.md` (stub marker until filled; `- R<n>:` layout rules), `<P>-LAYOUT.md` (`sketch:` = a `/gsd-sketch` folder whose README has a `winner:`, `pages:`, `url:`, `app:`, per-page `main_button:` / `expect:`, `waive:`), `<P>-UI-CHECK.md` (capture id + code hash), `<P>-UI-LOOK.md`, `<P>-UI-APPROVAL.md`, pictures + sheet in `<P>-SHOTS/` (git-ignored). Staleness = `gsd_ui_inputs_state` (`gsd_ui_code_state`, a tree hash of the working files outside `.planning/` built in a throwaway index, `+` the hash of `<P>-LAYOUT.md`) differs from the check's `code:` (an older check with no `+` is compared on the code hash only). A phase is exempt only when its `<P>-UI-REVIEW.md` is already on the base branch. `ui_gates = warn` (default) / `strict` / `off`. Bootstrap never creates `.planning/` (it would flip `/gsd-ingest-docs` into merge mode); the stub is made by the flow step.
- **`lib/ui-check.mjs`** — the Node runner behind `gsdt-ui check` (checks C1–C8, pictures, sheet, report). It resolves the PROJECT's Playwright with `createRequire` (a toolkit script cannot `import` project packages), falling back to the global npm folder (`gsd_ui_global_root`; tests pin `GSD_NPM_GLOBAL_ROOT` so the machine's own install never changes a result), uses the library API only (never a Playwright config), and writes into a run folder that `gsdt-ui` publishes only when the run finished. `lib/vendor/axe-core/` is a pinned copy (MPL-2.0, with its license); update `VERSION` with it. Everything the sheet shows is HTML-escaped. Doctor never imports or launches any of this.
- **`lib/context.sh`** — doctor's context section (`docs/plan-context-doctor.md`): `gsd_core_required_skills` (the gsd-core skills the flow and `gsdt-init` run — T009 checks these, not the profile name), the listing size of gsd-core's skills/agents (chars / 4), and the skill groups safe to hide (read from gsd-core's `clusters.cjs` with node, minus `.gsd-surface.json`'s disabled ones; a group is hideable only when none of its skills is required). Notes only; never edits gsd-core's files.
- **`lib/roadmap-audit.pl`** — read-only ROADMAP audit for `gsdt-doctor`. It catches two upstream gsd-core (`gsd_run`) bugs (`phase.insert` writes no checklist row; `phase.complete` can tick another phase's row).
- **Releases** (`docs/releases.md`) — `VERSION` is the package version. `install.sh` (standalone; runs via `curl | bash`, or `./install.sh` — a checkout installs the release too, never itself) downloads a release tarball + `SHA256SUMS`, verifies, and runs that package's `lib/install.sh` (an older release: `install.sh --copy`) into `…/share/gsd-toolkit/releases/<X.Y.Z>/`, keeping only the new and the previous release. `lib/install.sh` only copies (no link mode); `install.sh --copy` forwards to it, for older releases' `get.sh`. `bin/gsdt-update` re-runs its own runtime's `install.sh`; run from a git checkout it updates nothing. `lib/version.sh` holds the day-long cached latest-release check; `gsdt-start`/`gsdt-list` print the notice only when stderr is a tty (`GSD_UPDATE_NOTICE=always` forces it in tests), `gsdt-doctor` always notes it. `lib/install.sh` replaces links/skills it placed earlier (`owned_link`, `<!-- gsd-toolkit-skill X.Y.Z -->` line at the end of SKILL.md) instead of making `.bak` copies — a `.bak` on PATH or in a skill dir would load as real. The update repo is `malyeg/gsd-toolkit` (`GSD_UPDATE_REPO` overrides). **Old name:** before 0.8.0 the package was `gsd-worktrees` (`arconme/gsd-worktrees`, now archived; 0.7.1 there is the bridge release). Write only new names; READ both: tarball `gsd-worktrees-X.Y.Z.tar.gz` (install.sh picks the name from `SHA256SUMS`), runtime `share/gsd-worktrees/` (`owned_link`; install.sh removes it once nothing links into it), skill mark `<!-- gsd-worktrees-skill` (`GSD_SKILL_MARK_OLD`), `gsdw-*` skills (retired as no longer shipped), instruction markers `gsd-worktrees:<kind>:start/end` (`GSD_MARK_RE`; rewritten in place by bootstrap, T016 until then). `tests/test-update.sh` installs the real `v0.7.0` tag and moves it over in two hops.
- **`shims/`** — frozen 7-line delegators that bootstrap copies into target repos as `scripts/gsdt-*.sh`. Keep them unchanged: 0.10.0's rename (`scripts/gsd-*.sh` → `gsdt-*`) was the one change, and `gsdt-migrate` moves a repo over.
- **`mods/gsdt-batch-sonnet/`** — a Claude Code mod (hooks module, `register.ts`): while `/gsdt-batch` runs, MAIN-session `turn.step` requests go to `sonnet` (`e.agentId === undefined` only); off at the skill's `gsdt-batch: done` line, an aborted turn, session end, `/gsdt-batch-off`. Not installed by `install.sh`. Check it with `claude plugin validate` + `claude plugin test mods/gsdt-batch-sonnet` (local only: CI has no `claude`).
- **`skills/`** — `gsdt-worktrees`, `gsdt-flow`, `gsdt-tracker`, `gsdt-doctor` and `gsdt-batch`, installed per agent (install removes a toolkit skill it no longer ships). Never name a skill `gsd-*`: gsd-core's installer deletes every `skills/gsd-*` folder. They must stay provider-neutral: no literal `Skill()` calls. The flow skill only interprets `gsdt-flow-next` output; it is not a second state machine. Likewise `gsdt-doctor` only acts on `gsdt-doctor --json` (asking first); doctor itself stays read-only.

**Enforcement.** The mandatory guard is provider-neutral: `gsdt-worktree-guard --command … --phase … --repo …`. `gsdt-start` calls it before it prints or launches a session, and `gsdt-flow-next` calls it before it returns a step. Native hooks are extra defense only: Claude `PreToolUse(Skill)`. Codex has none. Exit 2 = block. The only escape hatch is `GSD_SKIP_GUARD=1`. One hook is user-level, not per repo: `lib/install.sh` registers `gsdt-worktree-guard --global` in `~/.claude` settings (next to the skills dir; `--no-user-hook` opts out) so `/gsd-new-project` and `/gsd-ingest-docs` are refused before `gsdt-init` (rule 0). It fires in every repo, so in a repo without `.gsd.conf` `--global` applies rule 0 only — never widen that. In a set-up repo it applies every rule (it is the only hook that sees typed slash commands; the repo hook sees `Skill` calls). It fails open on a payload it cannot read.

**Generated instructions (in target repos).** The workflow rules are not copied into repos: `gsdt-rules` prints them for the installed release (`gsd_rules_text`; + the repo's values via `gsd_repo_values`, and the screens paragraph unless `ui_gates = off`). Claude loads them with a user-level `SessionStart` hook (`gsdt-rules --hook`, registered by `lib/install.sh` next to the guard's `--global` hook; `--no-user-hook` drops both; it prints nothing outside a repo with `.gsd.conf` and always exits 0; keep its output well under ~10 KB, Claude Code cuts a larger one to a file). Codex/custom run `gsdt-rules` from the `AGENTS.md` line. `.gsd/INSTRUCTIONS.md` is canonical but small (providers, base, worktree dir — never `flow`/`ui_gates`, which `gsdt-rules` reads live — a core that holds without the toolkit, a pointer), between `canonical:start`/`end` markers. All block text lives in `lib/provider.sh` (`gsd_rules_text`, `gsd_canonical_block`, `gsd_provider_entry_block`): bootstrap writes it and doctor compares against it (T016 = out of date; T062 = Claude cannot load `gsdt-rules`), so edit it only there. `CLAUDE.md` / `AGENTS.md` (Codex + custom share it) get only a marked `gsd-toolkit:provider:start`/`end` entrypoint (`gsd-worktrees:` before 0.8.0, still read). Bootstrap validates markers before writing and never touches text outside them.

**Finish path.** `gsdt-finish` → `gsdt-wt-finish`: sync origin (abort on failure) → the gates (`gsd_finish_gates`: `gsd_ui_finish_gate`, then with `flow = strict` `gsd_flow_finish_gate`, the test audit; they read the branch from a throwaway worktree when its own is gone) → validate the phase (`scripts/gsdt-premerge-check.sh`, else the project's tests) → merge → `gsdt-planning-repair` → validate the combined tree → push with retry (repair and validate again after each retry's pull) → remove worktree + branch (files the finish's own test run left are removed; any other change keeps the worktree, exit 0) → `gsdt-tracker finish` (only with a tracker set). A failed validation keeps local commits and the worktree, and never pushes.

## Invariants to keep

- **`gsd-*` = gsd-core, `gsdt-*` = this toolkit.** Never name a command, shim or skill `gsd-*` (a lint in `tests/test-commands.sh` checks `bin/` and `shims/`). Since 0.10.0 there are no old-name aliases; what still reads an old name does so only to move it (`gsdt-migrate`, `lib/install.sh` pruning old links and replacing old user hooks, `gsdt-tracker` reading the `gsd-tracker.*` git section, legacy detection in bootstrap/doctor). Not renamed on purpose: the merge driver key `gsd-planning` (open worktrees' `.gitattributes` name it), `.gsd.conf`, `.gsd/`, `GSD_*`, `gsd_*` functions, `.git/gsd-cmd.lock`.
- One phase = one `phase-<N>-<slug>` worktree; one batch = one `batch-<date>-<slug>` worktree (`gsdt-batch` → `gsdt-wt-new --batch`; `gsdt-finish` lands it without the per-phase gates). The main checkout stays on the base branch. Find a phase's branch with `gsd_phase_branch` (a `/gsd-pr-branch` helper `X-pr` is skipped only when `X` exists, so a slug may end in `-pr`).
- Claims serialize through the base branch (pull, push, rebase-and-retry; the loser renumbers).
- A failed merge or validation must leave the remote base branch untouched.
- A `<P>-REVIEWS.md` counts only when `gsd_reviews_problem` (`lib/common.sh`) finds nothing: `gsdt-flow-next` and the guard share it. A review cut short by a usage limit is never a pass.
- The phase-flow artifact list (`<P>-CONTEXT.md`, `<P>-REVIEWS.md`, `<P>-REVIEW.md`, `<P>-VALIDATION.md` (`gsd_validation_problem`), `<P>-UI-REVIEW.md`, `<P>-LAYOUT.md`, `<P>-UI-CHECK.md`, `<P>-UI-LOOK.md`, `<P>-UI-APPROVAL.md`, …) is shared by `gsdt-flow-next`, the guard's `flow = strict` and `ui_gates = strict` rules, the finish gates (`gsd_flow_finish_gate`, `gsd_ui_finish_gate`), and gsdt-doctor's T040 report. Change them together.
- A UI check that could not run must never leave an older pass in place, and "not checked" is never reported as passed.
- Planning reconcile: keyed lines keep the **first** occurrence's position and the **best** occurrence's content (`[x]` beats `[ ]`, longer wins among equals). Single-value lines keep the last copy (the incoming branch). STATE.md's `## Session Continuity` must stay byte-identical — a test asserts it.
- `gsdt-doctor` is read-only by default. `--fix` (opt-in, asks y/N or `--yes`) runs only named safe actions — `gsdt-init --no-launch --no-commit`, `gsdt-planning-repair`, `git branch --track <base>`, `chmod +x` the pre-merge script, remove a dead lock — dispatched by name, never by eval of fix text; it never commits, pushes, checks out, deletes branches or edits ROADMAP.md. Add a code to the safe list only if its fix is mechanical and undoable. Finding codes: `W0xx` are shared with `/gsd-health`, `T0xx` are toolkit-only (e.g. `T050` bad providers list, `T059` bad model).
- `gemini` is refused with a reason everywhere (`providers`, `--provider`, `--agent`, `GSD_AGENT`, `review_provider`, `install.sh --agent`, `lib/install.sh --agent`); `gsdt-init --no-launch` removes an older release's Gemini setup.
- Legacy configs keep working: a singular `provider` key, `agent_command`, `--agent`, and `GSD_AGENT` are read-only compatibility inputs. With no provider configured, the default is Claude.
- macOS runs bash 3.2. There, `"$VAR…"` (a variable touching a non-ASCII character) is read as an unknown variable, and with the lock's EXIT trap an "unbound variable" crash **exits 0**. Always brace: `${VAR}…`. `tests/test-commands.sh` lints for it. Bash 3.2 also brace-expands `{2,4}` inside nested `"$( … "$( … )" )"` quotes: put such a regex in a variable first. Phase numbers may be zero-padded (`08`, `02.1` from gsd-core): never feed them to `$(( ))` without `10#`, and compare them numerically, not as strings.
- Scripts must work on both BSD (macOS) and GNU userlands. Shellcheck exceptions go in `.shellcheckrc` with a reason.
