GSD Command Order

One phase, from claiming the number to merging it back. Everything in the middle happens inside that phase's own worktree.

The whole loop

gsdt-flow-next N is authoritative: call it after each action. --all previews remaining steps, not permission to skip gates. Slash names below identify external planning skills; use your provider's supported invocation mechanism. Missing capability means handoff, not completion.

gsdt-start -n "description" --flow on the configured base branch; run the printed session command
Ticket snapshot only with a tracker; gsdt-tracker snapshot
/gsd-discuss-phase N agree the decisions
UI decision → design system → /gsd-sketch → /gsd-ui-phase Nask whether it has screens; if yes: DESIGN.md filled once, pick a sketch, approve the screens
/gsd-plan-phase N write the plan
Independent review → replan show findings; /gsd-plan-phase N --reviews

gsdt-ui check N → look → approve → /gsd-ui-review Nif it has screens, after code fixes

/gsd-secure-phase N security — every phase
gsdt-finish only after done and explicit user intent; final session action

What each one is for

  1. 1 gsdt-start -n "description" --flowon base Claims a phase, creates its worktree, and prints a provider session command. Run that command, or request --launch. Without --flow, start uses discuss-only behavior unless configured otherwise.
  2. 2 Ticket snapshot Only when .gsd.conf sets a tracker. Saves the phase's ticket (tk-<id> in its title) as <P>-TICKET.md with gsdt-tracker snapshot. No ticket yet? Ask for it; never fabricate product intent. Without a tracker this step is skipped.
  3. 3 /gsd-discuss-phase N Asks you the open questions and records your answers. This is where the real decisions get made, so do not rush it.
  4. 4 /gsd-ui-phase Nscreens only First ask whether the phase has screens. If yes: the project's design system (.planning/design/DESIGN.md, filled once), then /gsd-sketch and pick the winner into <P>-LAYOUT.md, then screen approval before planning. Otherwise pass --no-ui to the engine.
  5. 5 /gsd-plan-phase N Turns decisions into numbered plans. TDD mode is on by default (gsdt-start sets it): each plan for logic lists its test cases, input → expected result, so the review can check them, and execute writes each test before its code. Then obtain an independent review via the configured reviewer, show verified findings to the user, and replan with --reviews before execution. Missing reviewer capability requires a separate session handoff, not a skipped gate.
  6. 6 /gsd-execute-phase N Builds in waves, then runs the verifier. If verification reports gaps, plan with --gaps and execute --gaps-only; repeat until verified.
  7. 7 /gsd-verify-work N Agent-driven UAT checks the phase promises and records the result. Ask for clarification when required, but do not add an unconditional fourth approval gate.
  8. 8 /gsd-code-review N Reads the code the phase changed, looking for bugs and mess. Add --fix to apply what it finds.
  9. 9 /gsd-ui-review Nscreens only First gsdt-ui check N (app running) opens each page at phone, tablet and desktop size, measures it and takes the pictures. gsdt-ui look N lists what the agent must answer for every picture. Then you look at the sheet and say yes (gsdt-ui approve N). Then the review scores the built screens and compares them with the chosen sketch. Do it after the code review, not before.
  10. 10 /gsd-validate-phase Nevery phase Finds each requirement that has no test and writes the missing tests. It never changes the code itself. Runs after the code fixes, so the tests see the final code. A gap it cannot cover is marked manual-only, with your OK. Skipped only when the project turned off workflow.nyquist_validation.
  11. 11 /gsd-secure-phase Nevery phase Checks the security protections in the plan actually exist in the code. Run it for every phase, not only the ones that look security-related.
  12. 12 gsdt-finish Only after the engine reports done and the user explicitly requests landing. Validates, merges, revalidates combined code, pushes and removes the worktree. Final session action.

Not part of the loop

CommandUse it when
/gsd-quickA small job that does not deserve a whole phase. Still commits properly.
/gsd-fastTruly tiny — a typo, one line. Three file edits at most.
/gsd-debugHunting a bug. Keeps its notes so you can stop and come back.
/gsd-progressYou forgot where you are.
/gsd-resume-workComing back to a phase after a break or a lost session.
/gsd-pause-workStopping in the middle and want to pick it up cleanly later.
/gsd-audit-uatListing every test item still waiting on you, across all phases.
/gsd-audit-milestoneChecking a finished milestone against what you originally wanted.
/gsd-complete-milestoneClosing a milestone and starting the next.

The one rule that trips people up

Every command with a phase number runs inside that phase's worktree. The provider-neutral command guard blocks them anywhere else, and with flow = strict in .gsd.conf it also refuses a step whose predecessor left no artifact. The Claude native hook adds early feedback; Codex and hook-free sessions retain the same checks through gsdt-flow-next. Arbitrary shell commands that bypass GSD are outside this boundary.
